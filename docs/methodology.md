# Methodology

## What is detected and how
| Technique | Used for | Why |
|---|---|---|
| Regex + validators | emails, cards (Luhn), Aadhaar (Verhoeff), PAN (4th-letter check), keys, JWT, DB URLs, IPs, UPI, IFSC | fixed formats; checksums cut false positives |
| Context words | phone, bank account, passport, DOB, password, address | the same digits are harmless without context |
| spaCy NER via Presidio | person names, locations | no fixed format; needs a statistical model |
| Custom keywords | org-specific confidential terms | configured by an admin |

Scores are **heuristic**: pattern = base score, pattern + checksum/context = higher. They are not calibrated probabilities. A format or checksum match proves a value is *plausible*, never that it is *genuine*.

## Support levels
`reliable` (format/checksum), `moderate` (needs context or heuristic), `experimental` (ADDRESS, DATE_OF_BIRTH), `statistical` (PERSON, LOCATION). Shown live in Settings.

## Dataset (`evaluation/generate_dataset.py`)
* Seeded (default 42), fully synthetic: random values generated by code; fictional names; `example.*` domains.
* 219 documents: 155 positive, 25 plain benign, 39 hard negatives. 242 labeled spans over 13 labels.
* Sources: prompts, emails, support chats, code snippets, LLM-style responses. Includes multi-entity texts, Hinglish, different formatting.
* Hard negatives: bad-checksum Aadhaar/card, invalid-PAN look-alikes, order numbers, version strings, invalid IPs, hashes, placeholder keys.
* Annotations: exact half-open character offsets in `data/annotations/spans.jsonl`.

## Metrics (`evaluation/evaluate.py`)
* **Strict** precision/recall/F1: type and exact span must match. **Lenient**: same type and any overlap (shows boundary errors).
* **Benign FPR**: fraction of benign + hard-negative documents with at least one in-scope finding.
* **Leakage**: fraction of gold values still appearing verbatim in the sanitized text.
* **Latency**: scan time per document after warm-up (machine dependent).
* Only the 13 dataset labels are scored; other predicted types (e.g. LOCATION) are ignored and counted.
* Compared: `rules`, `nlp` (Presidio built-ins + spaCy only), `hybrid` (rules + spaCy names).

## Threats to validity (say these in your viva)
1. The same author wrote the generator and the rules, so synthetic scores are optimistic and say little about real-world data.
2. 219 documents is small; per-category numbers on 4-8 spans are noisy.
3. No public benchmark has been run yet, so none is claimed.
4. NER accuracy on Indian names is limited by the small English model.
